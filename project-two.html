Project 02

Takeaway Manager

An order and sales app for a fast food shop, built around a job I actually did. I managed my family's takeaway for eight months, so this is a problem I understand from behind the counter rather than one I read about.

  • HTML
  • CSS
  • JavaScript
  • Node.js
  • Express.js

In development. A live demo and source code link will appear here once the first version is deployed.

Why this project

Running the shop, the parts that cost the most time were the ones a computer should have been doing: keeping the menu and its prices straight, getting an order to the kitchen without it being misread, knowing which orders were still outstanding at a glance, and working out what the day had actually taken.

Most beginner portfolios are full of weather apps and to-do lists. This is the opposite of that. I know what the job needs because I did the job, and that is the part I could not have got from a tutorial.

What it will do

  • Menu management — add items, change prices, and retire items without breaking past orders.
  • Order entry — build an order by tapping menu items, with quantities and a running total.
  • Kitchen board — outstanding orders shown oldest first, marked off as they go out.
  • End of day takings — order count, gross total, and the best selling item.

How I'm building it

The process matters to me as much as the app. Every requirement starts as a written issue with a definition of done, each feature gets its own branch and pull request, and tests run automatically on every push before anything merges.

I'm building it in vertical slices, meaning one feature goes all the way from the database to the screen before the next one starts, rather than building a whole back end and hoping it fits the front end later. The rule I've set myself is that I don't merge code I can't explain out loud.

Decisions made up front

Two came straight from the shop floor. Money is stored in whole pence rather than decimals, because rounding errors in a till are real money. And an order stores a copy of each item's name and price at the moment it was placed, so putting a price up next month can't quietly rewrite what last month's takings were.
